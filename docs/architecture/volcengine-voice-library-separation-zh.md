# 火山引擎音色库解耦架构与运维规范（Control-Data Plane Separation）

## 1. 架构背景与问题定性

在接入火山引擎声音复刻（ICL）与大模型语音合成（TTS）能力时，传统思维容易陷入以下误区：
* **误区假设**：业务网关需要搭建一套音色文件托管服务，或者每次调用时去火山拉取音色音频文件，然后再把该音频文件作为“参考音频（Reference/Prompt Audio）”透传给音频生成接口。
* **事实与弊端**：
  1. **接口不支持常态文件托管**：火山音色设计/训练接口返回的试听音频（`demo_audio`）仅有 **1 小时临时签名有效期**，不可作为持久化音频源使用；
  2. **网络与带宽浪费巨大**：每次合成都跨网络拉取并转发几兆的音频文件，直接导致首包延迟（TTFT）增加数秒；
  3. **模型算力浪费**：大模型每次都要重新计算和提取参考音频的特征向量，无法利用云端预加载优化；
  4. **网关臃肿**：迫使核心网关引入复杂的对象存储（OSS/S3）、文件缓存及重型任务状态机。

## 2. 核心架构裁决：控制面与数据面彻底分离

经评审裁决，系统采用**“控制面与数据面分离（Control-Data Plane Separation）”**模式：

```
┌─────────────────────────────────────────────────────────────────────────┐
│                       控制面（Control Plane · 运维范畴）                 │
│                                                                         │
│   运营/录音音频/提示词 ──► [运维CLI工具 scripts/ops/volcengine-voice/]  │
│                                           │                             │
│                                           ▼                             │
│                       火山音色训练接口 (POST /api/v3/tts/voice_clone)   │
│                                           │                             │
│                                           ▼ 产出持久唯一标识             │
│                                      speaker_id                         │
│                                           │                             │
│                                           ▼ 登记入库                    │
│                                [前端/业务音色字典 JSON]                 │
└───────────────────────────────────────────┬─────────────────────────────┘
                                            │ 仅传递轻量 ID 映射
┌───────────────────────────────────────────▼─────────────────────────────┐
│                       数据面（Data Plane · 核心网关）                    │
│                                                                         │
│   客户端请求 ──► POST /v1/audio/speech { model, input, voice: "S_xxx" } │
│                                           │                             │
│                                           ▼ 极速鉴权与配额扣减           │
│                                     业务网关                            │
│                                           │                             │
│                                           ▼ 携带 speaker: "S_xxx" 转发   │
│                       火山大模型 TTS 接口 (POST /api/v3/tts/unidirectional)│
│                                           │                             │
│                                           ▼ 毫秒级首包流式音频          │
│   客户端播放 ◄──────────────────────── 实时音频流                       │
└─────────────────────────────────────────────────────────────────────────┘
```

### 职责边界定义

| 维度 | 控制面（音色训练与管理） | 数据面（音频生成） |
| :--- | :--- | :--- |
| **执行载体** | 独立运维 CLI 工具（`scripts/ops/volcengine-voice/`） | 核心网关（OpenAI 兼容 `/v1/audio/speech`） |
| **调用频率** | 极低频（按需录入、预制音色库、运营上架） | 极高频（业务实时调用、高并发流式合成） |
| **执行人员/主体**| 内部管理员、运营人员、音频工程脚本 | 终端用户、第三方 API 客户端、业务 Agent |
| **处理数据** | 大体积音频样本（WAV/MP3）、自然语言提示词 | 纯文本、字符流、音频输出二进制流 |
| **交付产物** | `speaker_id` 唯一音色代号 + 本地存档样音 | 最终合成语音流（MP3/WAV/PCM/Opus） |
| **计费与权限** | 消耗火山音色槽位费 / 训练设计次数（管理级密钥） | 按合成字符/时长计费（终端 Token 鉴权） |

## 3. 火山引擎官方接口对应关系

| 业务环节 | 官方接口路径 | 核心输入 | 核心输出 | 文档编号 |
| :--- | :--- | :--- | :--- | :--- |
| **音色设计**（提示词/图文） | `POST /api/v3/tts/voice_design` | `prompt` (文本/图片) + 预分配 `speaker_id` | `speaker_id` + `status` + 1小时临时 `demo_audio` | [2277844](https://docs.volcengine.com/docs/6561/2277844?lang=zh) |
| **音色训练/克隆**（真实音频） | `POST /api/v3/tts/voice_clone` | `audio.data` (Base64) + `speaker_id`/`custom_speaker_id` | `speaker_id` + `status` + 1小时临时 `demo_audio` | [2534906](https://docs.volcengine.com/docs/6561/2534906?lang=zh) |
| **大模型语音合成**（在线消费） | `POST /api/v3/tts/unidirectional` | `text` + `speaker` (即 `speaker_id`) | 实时音频二进制流（Chunked / SSE） | [1598757](https://www.volcengine.com/docs/6561/1598757) |

## 4. 运维与落地规范

### 4.1 控制面：音色克隆与产出
1. 音频准备：使用标准高质量录音（推荐 WAV/MP3，单声道 24kHz 以上，背景安静）；
2. 运行运维脚本（`voice-clone.js`），传入音频文件、语种及自定义音色代号；
3. 脚本自动调用火山 `/api/v3/tts/voice_clone` 完成特征固化；
4. **样音持久化**：脚本就地将火山返回的一小时临时 `demo_audio` 下载至本地 `demos/` 目录，便于上传至公开静态 CDN 供前端用户试听；
5. 输出音色配置 JSON，更新平台音色字典。

### 4.2 数据面：网关透明透传
1. 前端/客户端直接读取音色字典中的 `speaker_id`；
2. 客户端向网关发起标准请求：
   ```json
   {
     "model": "seed-audio-1.0",
     "input": "大家好，欢迎来到本期播客节目。",
     "voice": "custom_zh_anchor_01"
   }
   ```
3. 网关将 `voice` 参数映射为火山请求体的 `speaker` 字段，直接调用火山 TTS 单向流式或 WebSocket 接口；
4. 网关**不需要**保存任何音色音频，真正做到“零音色文件存储网关”。
