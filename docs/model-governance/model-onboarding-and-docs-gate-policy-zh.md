# OmniMux 新模型上架与独立开发文档同步门禁规范

## 一、核心原则
**“文档未更新，模型不上架；文档未验收，用户不可见。”**

所有新接入的大模型，在正式上架并开放给终端用户和开发者可见可用之前，必须严格确保独立开发文档仓库（OmniMux-docs）已完成同步更新并通过双语校验与版本更新日志登记。任何未经文档同步的模型，严禁开启生产公开状态。

---

## 二、标准上架流程（五步闭环）

1. **第一步：渠道实测与准入核验**
   - 采集渠道供货商控制台实拍截图与进价凭证；
   - 运行上游直连全模式测试，核验调用稳定性与出片质量；
   - 完成价格核算与台账凭证核验。

2. **第二步：底层接口适配与契约生成**
   - 完成网关底层协议对接与参数规范映射；
   - 自动生成模型能力契约档案与发布载荷；
   - 执行基础单元测试，确保底层完全连通。

3. **第三步：【核心门禁】独立开发文档同步与自测**
   - 切换至独立开发文档仓库（OmniMux-docs）；
   - 补充该模型的中英文接口调用文档与参数说明；
   - 在更新日志目录添加版本发布说明；
   - 执行文档格式与双语一致性自检，确保零错误。

4. **第四步：基线配置变更与生产部署**
   - 在网关配置基线中将该模型设为正式启用（公开可用）；
   - 执行自动化物理门禁核验（审计合规 + 契约载荷 + 文档同步）；
   - 通过蓝绿平滑发布通路同步至生产环境。

5. **第五步：线上回归验收与持续监控**
   - 执行真实网络端到端调用验收；
   - 确认开发者文档页面与前台模型展示同步生效；
   - 纳入平台全天候可用性监控。

---

## 三、三道物理硬门禁拦截体系

为杜绝跳步、漏步或人工遗忘，系统在三个核心节点设立了不可逾越的自动化硬卡点：

1. **第一道防线：日常工具操作实时拦截**
   - 当检测到有操作试图将新模型设置为启用状态时，实时探查独立开发文档仓库；
   - 若文档未同步或缺少更新日志，系统底层直接拒绝操作并阻断修改。

2. **第二道防线：代码提交前置卡点**
   - 在代码提交环节执行独立文档同步校验；
   - 凡包含公开可用但文档缺失的新模型，禁止提交代码。

3. **第三道防线：生产发布最终熔断**
   - 在配置正式写入线上生产数据库前，执行前置强校验；
   - 若文档未就绪，直接终止发布流程并安全回退，确保线上环境零污染。

---

## 四、异常处置与修复指引

当门禁触发阻断时，请按以下步骤整改：
1. 打开独立开发文档仓库；
2. 确认在中文与英文接口目录均已添加该模型的参数说明与调用示例；
3. 确认在更新日志中已录入该模型的发布条目；
4. 运行双语一致性检查无误后，重新触发上架与发布。
