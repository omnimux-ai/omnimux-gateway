# OmniMux 开发文档运维流程与技术语言规范

## 一、核心原则
**“开发文档唯服务于开发者接入，严禁添加非开发文档的语言描述。”**

独立开发文档仓库（OmniMux-docs）是面向外部开发者与技术集成方的官方接口参考手册。所有页面内容必须严格保持客观、严谨、精准的技术手册语体，坚决杜绝任何营销宣传口吻、内部叙述语言或主观修饰词汇。

---

## 二、语言规范与禁用红线

### 1. 严格禁止的语言描述（红线）
- ❌ **严禁营销与宣传话术**：如“颠覆行业”、“超强赋能”、“为您带来前所未有的体验”、“全网领先”等推销性文字。
- ❌ **严禁内部演进与思维叙述**：如“为了解决历史技术债务”、“经过团队反复讨论”、“本次重构优化了底层...”等非开发者关心的内部过程描述。
- ❌ **严禁口语化闲聊与客套**：如“亲爱的开发者您好”、“欢迎体验我们的强大功能”、“如果你觉得好用请...”等非技术客套话。
- ❌ **严禁虚假承诺与模糊用语**：如“极速秒出”、“无损高清”（应明确写具体秒数、具体分辨率参数）。

### 2. 必须采用的标准技术语体
- ✅ **客观的接口要素陈述**：
  - 接口端点（Endpoint）与请求方法（HTTP Method）；
  - 鉴权认证标头（Authorization: Bearer sk-...）；
  - 请求内容格式（Content-Type: application/json）；
- ✅ **严谨的参数规范表**：
  - 参数名称（精确字段名）；
  - 数据类型（string / integer / boolean / array / object）；
  - 必填属性（必填 / 可选）；
  - 明确的取值范围、枚举清单与边界约束；
- ✅ **规范的响应与错误码**：
  - 成功返回结构字段定义；
  - 400（参数校验错误）、401（未授权/无效令牌）、402（账户余额不足）等标准 HTTP 状态码说明；
- ✅ **可即时运行的代码调用示例**：
  - 遵循标准格式的完整请求体与响应体示例。

---

## 三、开发文档标准运维全流程（四步闭环）

1. **第一步：接口能力与参数基准对齐**
   - 提取模型底层真实支持的参数范围与数据约束，杜绝虚标。

2. **第二步：中英文同构技术文档编写**
   - 按照 Mintlify 标准，在对应接口目录同步编写中英文技术页面；
   - 必须保持中文路径（zh/）与英文路径（en/）同构对齐，无孤立页面。

3. **第三步：结构化版本更新日志登记与生成**
   - 在数据目录新增规范的更新条目，明确标注更新模型标识与技术文档链接；
   - 严禁手工修改已编译的更新页面，必须由生成脚本自动编译产出。

4. **第四步：自动化国际化自检与门禁放行**
   - 运行国际化对称性自检工具，确保双语内容 100% 完整无断链；
   - 经主网关独立文档门禁核验放行后，方可将模型设为公开在售。
